# Unified result kinds and producer identity

The merged writer uses **MCRSLT06** with an explicit layout discriminator. Both
pre-merge branches wrote the same magic with incompatible schemas, so the magic
alone does not identify a layout. No new result-kind number is allocated.

The little-endian envelope is:

1. 8 ASCII bytes `MCRSLT06`.
2. `u32::MAX` (a sentinel outside the permitted step-count range).
3. 16 ASCII bytes `FC-P4A-UNIFIED-1`.
4. `u32 step_count` (at most 10,000).
5. Name-sorted records: `u64 name_bytes`, UTF-8 name, 32 definition-hash bytes,
   `u8 kind`, `u64 payload_bytes`, bounded serde binary codec payload.

The ZIP manifest still verifies each part's size and SHA256. The discriminator is
part of those checked bytes. An unknown discriminator or an unmarked version 06
is rejected before any record is decoded, never retried under a different schema.
An old reader sees an invalid step count rather than interpreting new payloads.

| Kind | Unified payload |
|---|---|
| 0 | StaticResult without fatigue, including pretension results |
| 1 | FrequencyResult |
| 2 | HeatResult |
| 3 | ExplicitResult |
| 4 | FluidResult |
| 5 | Pre-mass HarmonicResult field order, without fatigue |
| 6 | Full linear Dynamics Response, including frames, spectrum flag, natural frequencies, warnings and energy ledger |
| 7 | Tuple (StaticResult including pretension, FatigueField) |
| 8 | Tuple (pre-mass HarmonicResult, FatigueField) |
| 9 | HarmonicResult with mass and operator_diagonal_bounds |
| 10 | Tuple (HarmonicResult with mass and operator_diagonal_bounds, FatigueField) |

The pre-mass harmonic order is step, nodes, reference_points, frames,
natural_frequencies, residual_vectors, stats, warnings. It implies consistent
mass, with no operator-diagonal diagnostic. Kinds 5/8 are written only when both
conditions hold; otherwise 9/10 preserve the actual selected mass. Fatigue is
skipped in the base codec and encoded once as the tuple's second member. Full
static results preserve nested nonlinear/contact/element data, including the
pretension field added by the merged branch. There is no optional fatigue trailer.

## Compatibility and recovery

Version 05 kinds 0–5 remain readable. Kind 0 uses the explicitly frozen pre-
pretension static schema, with empty pretension in the current result. Kinds 1–5
retain their original payloads. Version 05 kinds 6 and above are refused as
ambiguous. Other unsupported magic versions retain the existing result-drop note.

**All unmarked version 06 results require verified-producer recovery.** Before the
merge, the fatigue branch used 7=static+fatigue (without pretension), 8=legacy
harmonic+fatigue, 9=mass harmonic, 10=mass harmonic+fatigue. The dynamics branch used
6=legacy dynamics and 7=dynamics with energy, and its later mass extension used
10=dynamics with mass. Its merged prestress producer also changed the static
payload. A number or successful trial decode cannot establish these identities.

Keep each original file and SHA256. Open it only with its independently verified
producer binary/source; export a model without results and the original replies,
then regenerate with the merged native program where still needed. Compare the
complete result fields and record both identities and new file hashes. Never
change a header/tag byte as migration. Do not rerun large BASE responses to repair
metadata. Old and new frozen test fixtures have separate recorded producer
identities; the built-in current fixtures are generated by the merged program.

## Integration contracts

Kind 6 belongs exclusively to linear dynamics; it is now read and written in full,
not rejected as a placeholder. Future kind assignments require Router approval.
The random-frame pure evaluator and unaveraged element stress recovery coexist
with session-bound fatigue persistence and the stored harmonic mass identity.
Imported modal random steps retain their own supported contract; they do not
silently accept a fatigue request or a mass override. `solve.harmonic` accepts
`consistent|lumped`, default `consistent`; its mass governs assembly, modal
projection and mass-proportional damping. Random/fatigue inherit the solved source.
Lane 17's 5R remains a separately scheduled activity after user integration; this
merge does not execute it.
